# 经验：配音合成与字幕对齐

完整链路见 [`字幕与配音对齐-原理.md`](字幕与配音对齐-原理.md)。实现见 `tools/voice.mjs`（合成、自检、时间戳压缩）与 `src/app.js` 的 `narrate` / `narrPos`。

## 一、配音合成（豆包复刻音色）

1. **坏结果会复现，单纯重试无效。** 豆包偶发两种坏结果：①读到一半就结束（尾部没读）；②读完又多出一截无时间戳的语音。同一段文字往往每次都这样。对策：
   - 尾部没读：把没读的尾巴单独再合成一次，接在后面（最多 4 截）。
   - 多出语音：按最后一个词的结束时间 + 0.5 秒裁掉。
   - 拼接、裁剪都按 mp3 帧做（24 kHz MPEG-2 Layer III，每帧 24 ms），不重新编码。
2. **合成后必须自检，不过就当失败。** 三条：末尾有字没读；尾部无字幕音频 > 3 秒；句中停顿 > 4 秒。这三种都会让字幕与声音错位。`--fix` 只重做自检不过的段。
3. **换音色、改语速 = 全部重合成。** 曾连续两次全量重来（换复刻音色、再调 speech_rate -12）。以后先用 `--only` / `--from --to` 挑几段有代表性的（长段、多专名、引语）试听，参数定了再全量。
4. **缓存防重复计费。** 按文字哈希缓存，同文只合成一次；先写时间戳，再原子写 mp3（落盘即视为缓存完整）；上传失败重试不再合成。改字 → 哈希变 → 自动重合成。
5. **读音表 `data/lexicon.json`。** 多音字、古地名、人名注音；每次请求只带本段出现的词条。worker 交来的读音清单常混入大量无须注音的词，要人工筛。

## 二、字幕与声音对齐

1. **用服务端逐词时间戳，不按字数比例估。** `enable_subtitle` 返回逐词时间，按游标顺序 `indexOf` 回原文得字下标；对不上的词计入「未对齐」数，不静默丢弃。
2. **时间戳进 `data/voice.json` 的 `tm`。** 差分编码（厘秒差、字下标差），build 嵌入讲稿；前端按播放时间二分查找当前字下标。
3. **对不上时先查音频本身**（尾部没读、多余语音、长停顿），不要先去调前端。
4. **前端只读一个信号 `narrPos(文字, 下标)`。** 字幕分句、城邑闪标、政权高亮、镜头缓推都由它驱动。专名只在当前句里触发、同一实体至少隔 6 秒，防跳读乱闪；缓推时长取最后一个时间戳 + 0.5 秒。
5. **降级路径要齐。** 音频失败 → 浏览器朗读（字幕靠 `onboundary`）；关配音 → 按字数计时（约 85 ms/字）。Safari 须在点击时解锁音频。自动化测试（smoke、worker 自测）要静音。

## 三、流程与派活

1. **交互取舍先停下问。** 「镜头跟随」做完实测才发现几乎不触发且有害，最后删掉。
2. **讲稿文风** 三分文言，以 `data/film/06-1115.json` 为样稿，不打折扣。Pi 做史实核对可以，中文文风改写交给 sonnet。
3. **篇幅要写硬。** 计划里给字数上限并让 worker 自己核对（曾有讲稿约为素材 2 倍）。
