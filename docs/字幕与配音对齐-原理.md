# 字幕如何对齐声音：从讲稿到画面

本文讲全片讲解从写稿、合成配音到页面上字幕逐句跟读的完整链路。踩过的坑与对策另见 [`经验-配音与字幕.md`](经验-配音与字幕.md)。

```
data/film/*.json ──┐                       ┌─ .cache/voice/<fsha>.mp3   ──上传──► R2
（讲稿，一段一条）  │  npm run voice         │  .cache/voice/<fsha>.json  （逐词时间戳原文）
data/lexicon.json ─┼──► 豆包复刻音色合成 ──►┤
（读音表）          │   自检 / 补尾 / 裁剪    └─ data/voice.json  {base, au, tm}
                   │                                   │
                   └───────────── npm run build ◄──────┘  按文字哈希把 au（音频地址）、tm（压缩时间戳）填进每段
                                       │
                                       ▼
                     页面 narrate() 播音频，每帧按 currentTime 查 tm → 读到第几个字
                                       │  narrPos(文字, 字下标)
                     ┌─────────┬───────┴──────┬──────────┐
                   字幕分句   城邑闪标      政权高亮     镜头缓推
```

核心思路只有一条：**服务端给出每个词的开始时间，我们把它换算成「原文第几个字」，播放时按时间查出当前字下标，所有画面效果都只看这个下标。**

---

## 一、文案设计

### 1. 讲稿的单位：一段 = 一条音频 = 一个镜头停留

讲稿在 `data/film/*.json`，文件名顺序即播放顺序（01-936 … 10-1260），共 370 段、约 5.3 万字。每行一条，四种：

| 记录 | 含义 | 画面 |
|---|---|---|
| `{y:年, t}` | 换一幅疆域态势时的格局 | 回全景，显示新易手区域 |
| `{e:大事名, t}` | 大事讲解 | 飞到事件及相关城邑的取景框 |
| `{e:大事名, s:k, t}` | 战役第 k 步 | 演示该步行军/占领动画 |
| `{e:大事名, s:"end", t}` | 战役收尾 | 停在最后一步 |

页面地址 `#f=段号` 与 `npm run voice -- --from/--to` 的段号是同一套（从 1 起）。

为什么按段切：镜头、动画、讲解三者以段为同步单位。每段开始时镜头先飞到位（`flyTo`），然后才开始读；读完且动画也结束后停 600 ms 进下一段（`filmSay`）。段内的细同步才靠时间戳。

### 2. 句子：字幕按句显示

字幕不是逐字滚动，而是**一次显示一整句**，读到下一句时换掉（淡入 150 ms）。断句规则在 `syncParse`：

- 在 `。！？；` 处断开；紧跟的闭合符号 `”’」』）》` 归前一句。
- 逗号不断句，所以一句不宜过长：超过 34 字的句子字幕自动换小一号（`.long`），再长就会折成多行、压住地图。
- 写稿时宜多用句号，一句话说一件事。

### 3. 文风与可听性

- 约三分文言七分白话，以 `data/film/06-1115.json` 为样稿；引语用「曰」「道」引出，不依赖引号（引号在合成与对齐时都被当作标点忽略）。
- 写给耳朵听：同音易混的词换说法；人名、地名首次出现给全称。
- **专名照字典写**：字幕里政权名、城邑名会加粗着色并在地图上闪一下，匹配来源是当年在场的政权名（含别名）、城邑全名、去括注名、去京号名（东京开封府→开封府）、去「府州军城寨堡」的简称，以及 `data/alias.json`。写成字典里没有的叫法就不会触发联动；需要时往 `alias.json` 加别名。单字政权名（如「金」「辽」）只在后接「军朝国人廷主帝兵将境」之一时才算。

### 4. 读音表 `data/lexicon.json`

多音字、古地名、人名的注音，一行一条：`"澶渊/(chan2)(yuan1)"`。合成时只把本段出现的词条随请求发出（`pronunciation_dict`）。长词与短词并存时都列（如「燕京」「燕京都」）。词条变动会改变受影响段的缓存键，下次 `npm run voice` 自动重合成这些段。

### 5. 改稿流程

1. `npm run read` 生成 `dist/全片讲稿-通读稿.md`：按播放顺序、一句一行、每段标段号，便于通读和整段改。
2. 改完 `node tools/readthrough.mjs --apply 文件` 按段号写回 `data/film`（可只含改过的段）。
3. `npm run voice -- --dry` 看有多少段因文字变化待重合成、共多少字（计费字数）。
4. 先 `--from N --to N` 合成一两段试听，再全量 `npm run voice`。

**任何一个字改动都会让这段需要重新配音**——音频是按文字哈希找的，找不到就会退回浏览器朗读。

## 二、生成音频（`tools/voice.mjs`）

### 1. 两个哈希

- **文字哈希 `tsha`** = sha256(文字) 前 16 位。`data/voice.json` 以它为键：同样的文字只合成一次，build 也按它把音频挂到讲稿段上。
- **文件哈希 `fsha`** = sha256({文字, 音色, 合成参数, 本段读音词条}) 前 16 位，即音频文件名。换音色、改语速、改读音表都会让 `fsha` 变化，于是 `au[tsha] !== 新文件名`，这段自动进入待合成。

### 2. 合成请求

- 豆包语音合成 v3 单向流式接口，资源 `seed-icl-2.0`（声音复刻 2.0），参数 `mp3 / 24 kHz / speech_rate -12 / enable_subtitle:true`，`tone_fidelity:true`。
- `enable_subtitle` 让响应里带回逐句、逐词的时间戳：`{sentence:{text, words:[{word, startTime, endTime}]}}`，单位秒。
- 响应是一串 JSON 对象，`parseObjects` 逐个切出；音频是各对象 `data` 字段的 base64 片段拼接。

### 3. 修复坏结果：补尾与裁剪

豆包会偶发：①读到一半就结束；②读完后多出一截没有时间戳的语音。同一段文字常反复出现，重试无用。`synthesize` 的处理：

1. 用游标把返回的每个词按顺序 `indexOf` 回原文，得到读到了原文第几个字（`cursor`）和最后一个词的结束时间。
2. **裁剪**：只保留到最后一个词结束后 0.5 秒的音频，多读的那截丢掉。
3. **补尾**：若 `cursor` 之后还有非标点文字，把剩下的尾巴单独再发一次合成，音频接在后面，时间戳整体加上前面音频的时长 `t0`。最多拼 4 截。
4. 拼接与裁剪都按 mp3 帧操作：24 kHz MPEG-2 Layer III 每帧 576 样本 = 24 ms，`mp3Frames` 解析帧头、跳过 ID3 与 Xing/Info 帧，直接拼帧，不重新编码。

### 4. 自检（`takeIssue`）

合成结果必须通过三条，否则抛错重试（最多 3 次）：

| 检查 | 阈值 | 后果 |
|---|---|---|
| 末尾有字没读 | > 0 字 | 字幕读不到最后一句 |
| 尾部无字幕的音频 | > 3 秒 | 字幕结束后声音还在 |
| 句中两词间停顿 | > 4 秒 | 字幕卡住不动 |

`npm run voice -- --fix` 对已合成的段重新跑这三条，只重做不合格的。

### 5. 落盘、上传、清单

1. 先写时间戳 `.cache/voice/<fsha>.json`（服务端原始逐词数据，补尾后已平移），再把 mp3 写成 `.tmp` 后原子改名。mp3 存在即视为缓存完整，上传失败重试时不再计费合成。
2. mp3 与 json 用 SigV4 签名上传到 R2（地址前缀为 `.env` 的 `VOICE_BASE`）。
3. 压缩时间戳写进 `data/voice.json`：`au[tsha]=文件名`、`tm[tsha]=压缩数组`。每完成一段就保存一次；文字已不在讲稿里的条目自动清掉。
4. 只缺时间戳时 `npm run voice -- --tm` 从本地缓存或 R2 读 json 补全，不调合成。

## 三、时间戳：从「词 + 秒」到「秒 → 字下标」

### 1. 对齐到原文（`compressTiming`）

服务端的词是它自己切的（一个字或一个词），且会略去标点。逐个在原文里从游标处往后 `indexOf`：找到就记下 `(开始时间, 原文字下标)`，游标移到词尾；找不到计入「未对齐」数（`npm run voice` 结束时会报），跳过该词而不中断。要求时间单调不减，否则报错。

### 2. 压缩格式

`tm` 是扁平整数数组，两两一组：`[厘秒, 字下标, Δ厘秒, Δ字下标, …]`，首组为绝对值，之后都是与前一组的差值。差值多为 1—2 位数，`voice.json` 因此很小。

例：`[0,0, 27,1, 42,2, 24,1, …]` 解出

| 时间（秒） | 0.00 | 0.27 | 0.69 | 0.93 |
|---|---|---|---|---|
| 字下标 | 0 | 1 | 3 | 4 |

即 0.69 秒开始读第 3 个字（第 1—2 字是一个词）。

### 3. build 嵌入

`tools/data.mjs` 组装数据时，对每段讲稿算 `tsha`，在 `voice.json` 里查到就填 `au = base + '/' + 文件名`、`tm = 压缩数组`。产物 HTML 里只有地址和时间戳，音频从 R2 按需加载。

## 四、页面播放（`src/app.js`）

### 1. `narrate(文字, 音频, 最短毫秒, tm)`

所有自动讲解都走它，返回 `{done, stop}`。三条路径：

| 情况 | 声音 | 读字位置来源 |
|---|---|---|
| 开配音且有音频 | 播 mp3 | 每帧 `audio.currentTime` → `tmAt` 二分查找 → 字下标；无 tm 时按 `currentTime/时长` 比例估 |
| 开配音但无音频，或音频加载/播放失败 | 浏览器 `speechSynthesis` 朗读 | `onboundary` 事件给出的 `charIndex` |
| 关配音 | 无 | 经过时间 / 估算时长 × 字数；估算时长 = max(最短毫秒, 字数 × 85 ms) |

最短毫秒：站点段 4000，战役步骤 2400。音频自然结束时报 `文字长度`，表示读完；被打断（换段、暂停、新的 narrate）时报 `null`。

`tmAt(map, 秒)`：在 `T[]` 里找最后一个 ≤ 当前秒的位置，返回对应的 `P[]`（字下标）；当前秒小于首词时间时返回 0。

全程复用同一个 `Audio` 元素：第一次在点击「播放」时解锁，之后自动连播不会被 Safari 的自动播放策略拦下。

### 2. 唯一信号 `narrPos(文字, 字下标)`

`narrate` 只在字下标变化时调用它。画面同步全部从这里出发，彼此不直接通信：

- **字幕**：用 `syncParse` 的分句表 `S=[[起,止],…]` 找到字下标所在句；句子变了就换上该句已预渲染好的 HTML（专名已加粗着色）。读完后 0.9 秒隐藏。只在全片播放或战役演示时显示。
- **城邑闪标 / 政权高亮**：专名表 `M` 按起始下标排序，字下标越过某个专名的起点就触发一次（脉冲环或疆域描边加粗，约 2.5 秒）。只触发当前句里的（跳读时略过前句），同一实体两次触发至少隔 6 秒。
- **镜头缓推**：段开始时按本段时长做一次缓慢推近；时长 = 最后一个时间戳 + 0.5 秒（有配音时），关配音时按字数估。用户本段动过地图就不推。

分句与专名表按「年份 + 文字」缓存，`narrPos` 里只做下标比较和少量 DOM 改动，每帧开销很小。

### 3. 一段的完整时序

```
filmShow(i)：摆好年份/态势/高亮 → flyTo(取景) 等镜头到位
  └─ filmSay：narrate(t, au, 最短毫秒, tm)
       ├─ 每帧：currentTime → tmAt → narrPos → 换句 / 闪标 / 缓推
       └─ 音频结束 → narrPos(文字长度) → done
     等 done 且动画结束 → 停 600 ms → filmShow(i+1)
```

战役单独演示时（不在全片里），每步走同样的 `narrate`（`stepNarr`）：优先用全片讲稿里该战役该步的那段（文字、音频、时间戳都现成）；没有才退回 `events` 里步骤自带的文字 `[0]`、音频 `[3]`、时间戳 `[4]`。

## 五、常用命令速查

| 目的 | 命令 |
|---|---|
| 通读稿 | `npm run read` |
| 写回改过的通读稿 | `node tools/readthrough.mjs --apply 文件` |
| 看待合成段数与字数 | `npm run voice -- --dry` |
| 试听几段 | `npm run voice -- --from 120 --to 122`（或 `--only 文字前缀`） |
| 强制重合成选中段 | 再加 `--redo` |
| 只重做自检不过的段 | `npm run voice -- --fix` |
| 只补时间戳 | `npm run voice -- --tm` |
| 检查线上音频都在 | `npm run voice -- --verify` |
| 回归测试 | `npm run smoke`（改了 app.js 必跑） |

凭据只读项目根目录 `.env`（`VOLC_API_KEY`、`VOLC_SPEAKER`、`R2_*`、`VOICE_BASE`）。全部音频与时间戳的备份见 GitHub Release `voice-v2`，解压到 `.cache/voice/` 即可恢复本地缓存。
